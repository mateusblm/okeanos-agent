# Credits

The cycle (measure, identify, fix, verify, protect), the keep-or-revert table with "neutral is a revert", the attempt log, the rule that correctness gates the metric, and most of `PATTERNS.md` (query plans before indexes, connection pools, cache keys and staleness, Core Web Vitals, images, code splitting, budgets) are adapted from [Addy Osmani](https://github.com/addyosmani)'s [`performance-optimization`](https://github.com/addyosmani/agent-skills/tree/main/skills/performance-optimization) skill and its references. The metric-honesty rule (no measurement, no number; unmeasured findings labelled "potential impact"; lab and field data named and kept apart) is adapted from his [`web-performance-auditor`](https://github.com/addyosmani/agent-skills/blob/main/agents/web-performance-auditor.md) agent. Both MIT, Copyright (c) 2025 Addy Osmani.

The benchmark checklist in `PATTERNS.md` (the seven questions), the report format (number with unit, run count, range, limiter; "inconclusive" when the limiter is unknown) and "why not twice as fast?" are adapted from [Lauren Tan](https://github.com/poteto)'s [`benchmark-checklist`](https://github.com/cursor/plugins/tree/main/pstack/skills/benchmark-checklist) and [`principle-explain-the-number`](https://github.com/cursor/plugins/tree/main/pstack/skills/principle-explain-the-number) skills; the cheapest-first ladder of fixes in step 3 comes from the performance mantras in her [perf-issue playbook](https://github.com/cursor/plugins/tree/main/pstack/skills/poteto-mode/playbooks/perf-issue.md). MIT, Copyright (c) 2026 Lauren Tan.

The adaptation drops tool- and vendor-specific commands, framework-specific code samples and the audit report template, sends the attempt log to the PR body or the publish-gate summary, and turns the guard step into a test or a budget check in `docs/agents/checks.json`.
